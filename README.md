# Secret Message / 秘密消息

一个**纯前端、纯离线、无需服务器**的安全消息交换工具。

双方先交换公开连接码，在各自设备上通过 ECDH 建立同一把会话密钥；核对安全码后，后续消息都只使用这把本地会话密钥进行 AES-256-GCM 加密和解密。

> 页面不会上传你的消息、私钥或会话密钥。私钥和会话密钥都不会显示给用户，也不会写入浏览器持久化存储。

## 在线使用

GitHub Pages：部署完成后可直接打开项目 Pages 地址使用。

该网页本身不依赖任何网络 API、CDN、远程字体或第三方脚本。即使通过 GitHub Pages 加载，页面加载完成后的密码学操作全部在本机完成。

## 为什么做这个工具

很多“在线加密工具”要求用户自己理解公钥、私钥、RSA、AES、密钥导入导出等概念，操作复杂，而且容易把真正需要保密的材料复制到错误的位置。

这个项目只保留普通用户真正需要做的事情：

1. 双方各自打开页面。
2. 互相发送页面生成的**公开连接码**。
3. 页面在各自设备上自动计算共同会话密钥。
4. 双方通过电话、当面或另一个可信渠道核对同一组数字。
5. 核对一致后，就可以互相发送密文。

整个过程中，用户**不需要复制私钥，也看不到私钥**。

## 安全模型

### 被动窃听

攻击者可以看到：

- Alice 的公开连接码
- Bob 的公开连接码
- 双方之后交换的所有密文

这不足以计算双方的共享会话密钥。

双方使用 ECDH P-256：Alice 使用自己的私钥和 Bob 的公开信息，Bob 使用自己的私钥和 Alice 的公开信息，各自在本机得到相同的共享秘密。旁观者只有双方公开信息，无法得到对应私钥。

### 主动中间人攻击

仅仅交换公开连接码不能自动证明“这个连接码确实属于对方”。攻击者可以尝试替换双方看到的连接码，并分别与两端建立连接。

因此本工具把**安全码核对**作为协议的强制步骤：

- 双方会独立得到同一组 12 位核对码。
- 用户必须通过另一个可信渠道比较核对码。
- 在用户确认一致之前，Worker 会拒绝消息加密和解密。

如果核对码不同，不应继续通信。

## 密码学设计

- 密钥协商：ECDH P-256
- 密钥派生：HKDF-SHA-256
- 消息加密：AES-256-GCM
- 每条消息使用新的随机 96 位 IV
- 每条消息包含随机消息 ID
- 协议版本、会话 ID、消息 ID 作为 AES-GCM Additional Authenticated Data
- 篡改后的密文会认证失败
- 其他会话生成的密文会被拒绝
- 当前页面已成功打开过的消息 ID 会被拒绝再次打开

## 不留存设计

私钥和会话密钥只存在当前 Web Worker 的内存中，并且以不可导出的 `CryptoKey` 形式保存。

项目不使用：

- `localStorage`
- `sessionStorage`
- IndexedDB
- Cookie
- Service Worker 缓存

以下操作都会丢弃当前连接：

- 刷新页面
- 关闭页面
- 点击“结束并清空”
- 默认 10 分钟无操作

由于 JavaScript 字符串和浏览器内存由运行时管理，网页无法保证历史内存被物理覆写。因此这里的“不留存”指：**不主动把敏感信息写入持久化存储，并尽快销毁持有密钥的 Worker。**

## 完全离线

项目没有运行时依赖：

- 无 npm 前端依赖
- 无 CDN
- 无远程字体
- 无分析统计
- 无后端 API
- CSP 使用 `connect-src 'none'`

下载仓库后，可以断开互联网再使用。

本地启动：

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

然后打开：

```text
http://127.0.0.1:4173
```

也可以使用：

```bash
npm run serve
```

## 测试

```bash
npm test
```

当前自动化测试覆盖：

- 私钥不可导出
- 页面状态不暴露私钥或会话密钥
- 双方独立派生相同会话 ID
- 双方独立派生相同安全核对码
- 会话密钥不可导出
- 未完成安全核对前禁止加密和解密
- 核对完成后支持双向消息
- 相同明文产生不同随机密文
- 篡改密文拒绝
- 其他会话密文拒绝
- 重复消息拒绝
- 自连接拒绝

## 浏览器要求

需要支持 Web Crypto API、ECDH、HKDF、AES-GCM 和模块化 Web Worker 的现代浏览器。

建议使用近期版本的 Chrome、Edge、Firefox 或 Safari。

## 适用范围

这个项目适合：

- 临时交换密码、账号、地址、恢复信息等机密文本
- 在不可信聊天工具中传递加密后的内容
- 不希望把私钥交给网页服务器或云服务的场景
- 需要一个无需安装、无需账号的临时安全会话工具

它不是完整的 Signal 替代品，也没有长期身份、联系人目录、多设备同步、双棘轮协议或持久化历史记录。它的目标是把“一次安全会话”做得尽可能简单、透明和离线。
